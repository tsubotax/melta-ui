# レポート出力テンプレート

> SKILL.md Step 5 の詳細。

---

## 出力ルール

- 同一の違反クラスが複数箇所にある場合は1件として集約し「（N箇所: 行XX, XX）」と付記する
- 各違反に行番号（HTMLソース内の位置）を必ず付記する
- **各違反にルール ID を付記する**（`design/contracts/rules.json` に実在する ID のみ。存在しない ID を書かない）
- **「人間確認待ち」は違反件数に含めない**: サマリー表の「人間確認待ち」行は `## 評価不可` 節の件数であり、Critical〜Low の合計（= 検出違反数）とは別に数える
- **箇所数カウントの精度**: `text-black` / `text-gray-400` 等のクラスをカウントする際は、Tailwind CSSクラスとしてテキスト要素（`<p>`, `<span>`, `<td>`, `<h1>`〜`<h6>`, `<a>`, `<label>` 等）の `class` 属性に付与されているもののみをカウントする。SVG属性（`fill`, `stroke`）の色指定や、非テキスト要素への適用は区別し、重複カウントしない
- **サマリー整合チェック**: レポート完成後、本文中の各重大度の件数を数え、冒頭サマリーの件数と一致することを確認する。不一致があれば修正してから出力する

---

## テンプレート

```markdown
# デザインレビューレポート

**対象ファイル**: [ファイル名]
**検出違反数**: N件（Critical〜Low の合計。人間確認待ちは含まない）

| 重大度 | 件数 |
|--------|------|
| Critical | N |
| High | N |
| Medium | N |
| Low | N |

## 違反詳細

### カラー

- [重大度] **`text-black`**（N箇所: 行XX, XX）— 理由 → `text-slate-900` `[COLOR_NO_TEXT_BLACK]`

### スペーシング・レイアウト
...

### タイポグラフィ
...

### モーション
...

### ボーダー
...

### フォーム
...（複合修正が必要な場合はコードブロックで修正例を提示）

### アクセシビリティ
...

## 評価不可

| aspect | reason | proposal |
|--------|--------|----------|
| Drawer のフォーカストラップ `[SPACE_NO_DRAWER_NO_FOCUS_TRAP]` | human-only | 実機で Tab / Shift+Tab の循環を確認する |
| （観点） | not-observable-static | （人間が何を確認すればよいか） |
| （観点） | ルール無し | （rules.json にルールを足すか、指摘を取り下げるか） |

## 適合確認
（正しく実装されている主要な点を箇条書き）
```

---

## `## 評価不可` 節の書き方

- `reason` は3種のみ: `human-only`（rules.json の `automationStatus` が human-only）/ `not-observable-static`（静的 HTML では観測できない挙動）/ `ルール無し`（対応するルールが rules.json に無い）
- ここに載せた項目は **違反件数に数えない**。Critical〜Low のどこにも入れない
- 該当ルールがある場合は ID を併記する。`ルール無し` の行には ID を書かない
